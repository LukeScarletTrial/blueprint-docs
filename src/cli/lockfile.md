# Printable Lockfile & Dependency Management (`bl.lock`)

When building reproducible applications, dependency versions must remain deterministic across multiple machines, CI pipelines, and developer environments. Printable manages this through `config.bls` and `bl.lock`.

---

## The Lockfile Concept

- **`config.bls`** defines your project's high-level requirements (e.g. `core: "1.0.0"`, `vector: "latest"`, or a Git URL).
- **`bl.lock`** is automatically generated by Printable whenever you run `printable install`, `printable add`, or `printable update`. It records:
  - Exact package names
  - Specific version numbers resolved
  - Local resolved path (e.g. `modules/vector`)
  - Integrity checksums

---

## Example `bl.lock` File

```json
{
  "version": "1.0.0",
  "packages": {
    "shapes": {
      "name": "shapes",
      "version": "1.0.0",
      "resolved": "modules/shapes",
      "integrity": "sha256-shapes"
    },
    "vector": {
      "name": "vector",
      "version": "1.0.0",
      "resolved": "modules/vector",
      "integrity": "sha256-vector"
    }
  }
}
```

---

## Managing Dependencies with CLI

### Adding a Dependency
```bash
printable add https://github.com/LukeScarletTrial/blueprint-shapes.git
```
This clones or downloads the package into `./modules/shapes`, updates `config.bls`, and regenerates `bl.lock`.

### Removing a Dependency
```bash
printable remove shapes
```
Cleans up the entry in `config.bls`, removes the files under `./modules/shapes`, and refreshes `bl.lock`.

### Updating Dependencies
```bash
printable update
```
Fetches the newest versions of all declared dependencies and re-syncs `bl.lock`.
